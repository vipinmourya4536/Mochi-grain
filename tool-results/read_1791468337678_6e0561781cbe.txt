    61→Work Log:
    62→- While verifying computed styles via agent-browser, found `backdrop-filter` computed as `none` on nav/header/cards despite being in the source CSS.
    63→- Root cause: Tailwind v4's LightningCSS strips the STANDARD `backdrop-filter` declaration whenever a `-webkit-backdrop-filter` twin is present in the same rule (treats it as legacy-target redundancy), emitting only the prefixed form. Chrome does not alias the prefixed form, so ALL 13 glass surfaces (nav, header frost layer, cards, insight card, toast, badges, language panel) silently had NO blur in Chrome/Edge/Firefox — only iOS Safari (native -webkit- support) rendered the frost. Bug shipped in the upstream repo.
    64→- Fix: removed all 13 `-webkit-backdrop-filter:` duplicate lines from src/app/globals.css, keeping only the standard property. LightningCSS now preserves the standard declaration and auto-emits the `-webkit-` twin itself (verified in served CSS: STD: 13, WK: 13).
    65→- Verified in-browser: `getComputedStyle(nav).backdropFilter === 'blur(28px) saturate(1.6)'`; scrolled screenshots show content visibly blurred behind header + bottom nav in both dark and light modes.
