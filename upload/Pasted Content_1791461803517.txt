==================================================
1. PRIMARY FUNCTIONAL BUG: GRAIN SELECTION IS NOT A SINGLE SOURCE OF TRUTH
==================================================

Current problem:

The Settings screen allows selecting Wheat, Rice, Corn, Barley, Soybean, Sorghum, Oats, Millet, etc.

However:
- `selectGrainType()` updates `settings.grainType`
- Home `MetricPills` currently displays `currentReading.grainType`
- `HeroCard` also currently uses `currentReading.grainType`
- BLE data is parsed with a grain code inside `bluetooth.ts`
- `handleReading()` updates `deviceInfo.grainType` from the incoming BLE reading

This creates a mismatch.

Observed behavior:
I can change the grain in Settings from Corn to Wheat/Soybean/Rice/etc, return Home, and Home can still visually say Corn.

This must be completely fixed.

NEW ARCHITECTURE:

`settings.grainType` must be the authoritative user-selected grain for the application.

The selected grain determines:
- Home UI grain label
- Mochi thresholds
- Mochi decision evaluation
- risk state
- Discover recommendations
- current reading’s displayed grain
- new history records captured by the app

The ESP32 BLE packet may still contain a grain code, but that should NOT silently overwrite the user’s selected grain.

Do NOT allow this flow anymore:

BLE grain code
→ overwrite app grain selection
→ Home changes unexpectedly

Instead:

User-selected grain in Settings
→ application source of truth
→ Home
→ Mochi thresholds
→ Mochi decision
→ history

BLE should primarily provide:
- moisture
- temperature
- battery
- signal
- device state

If the firmware grain code is useful, preserve it only as optional diagnostic/device metadata. It must not override the application-selected grain unless there is an explicit future “use device grain” action.

- risk state if thresholds differ
- Discover contextual recommendations

Do not mutate historical timestamps merely because the selected grain changes.

==================================================
FINAL DESIGN PRINCIPLE
==================================================

The finished Mochi Grain app should feel like:

a precision agricultural instrument wrapped in subtle physical glass.

Not:
- a generic dashboard
- a UI kit demo
- a collection of rounded cards
- an overly animated mobile app
- a black-and-white glassmorphism template

The visual hierarchy must be clear.

The selected grain must have one source of truth.

Settings chooses the grain.

Home interprets the grain.

Mochi evaluates the grain.

History records the grain.

Discover teaches the grain.

BLE provides measurements, not authority over the user’s selected monitoring profile.

Make the interface feel calm, precise, tactile, and finished.
